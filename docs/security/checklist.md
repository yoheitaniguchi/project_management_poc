# セキュリティレビュー チェックリスト

`security-reviewer`エージェント・`/security-review`スラッシュコマンドが参照する正本。
姉妹リポジトリ `production_system_sim` のチェックリストを、このPoCの前提に合わせて書き換えたもの。
観点のもとは CLAUDE.md 4章（データの守るべきルール）・6.1〜6.4。

`security-reviewer`は各項目について、該当箇所がある場合は「ファイル:行」「根拠」「重大度
（Critical/High/Medium/Low/Info）」を、該当なしの場合は「該当なし＋理由」を記録すること。
重大度は「実際に悪用可能で影響が大きい＝High以上、到達不能・理論上のみ＝Low」を基準とし、
断定できない場合は根拠と不確実性を併記して**推測で重大度を上げない**こと。

## 前提（このリポジトリの実態）

- **バックエンドを持たない1ページのアプリ**（React + TypeScript + Vite）。認証・セッション・DBは無い
- **リポジトリとGitHub Pagesのサイトは公開されている**。PoCの実データ（企画の内容、WBS、実績工数、書き出したJSON・CSV）は利用者のブラウザ（localStorage）とPCにだけ置き、リポジトリにもビルド成果物にも含めない
- localStorageのオリジン `yoheitaniguchi.github.io` は姉妹リポジトリと共有している（リスクは受け入れ済み。CLAUDE.md 6.1）
- Asana APIは使わない。Asanaとのやり取りはCSVファイルのみで、トークンは扱わない
- 外部入力は、利用者が読み込むファイル（独自書式のCSV、AsanaのCSV、保存したJSON）だけ
- 利用者は1名。承認者・操作者は自己申告

## A. 公開リポジトリと実データ

- 実データがコード・テスト素材・ドキュメント・**コミット履歴**・ビルド成果物（`dist/`）に含まれていない
- `.gitignore`で、アプリが書き出すファイル（接頭辞 `pmpoc-`）と `.env*`（`.env.example`を除く）を除外している
- テスト用のCSV・JSONは決められた置き場（`src/**/__fixtures__/`）にだけあり、架空のデータである。CIで置き場以外の`*.json`/`*.csv`の追加を検査している（設定ファイルを除く）
- 週次報告・評価レポートに個人別の実績工数を載せていない
- 秘密情報（トークン・パスワード等）がコード・設定・履歴に無い（`gitleaks`）。秘密情報を扱うコードが現れたこと自体を指摘する

## B. 外部通信

- アプリが外部へ通信していない（`fetch`・`XMLHttpRequest`・外部のスクリプト・フォント・画像・解析タグ）
- 本番ビルドの`index.html`にCSP（`default-src 'self'; connect-src 'none'; object-src 'none'; base-uri 'self'`）があり、開発時だけの例外が本番に漏れていない

## C. 入力の検証と出力の無害化

### 読み込むファイル（JSON・CSV）
- 検証関数は`unknown`を受けて型ガードで絞っている（`any`や`as`で検証をすり抜けていない）
- ファイルサイズ・配列の件数・文字列の長さに上限がある
- IDが一意で、参照先（objective・wbs_node・baseline・member）が存在する
- WBSの親子に循環が無いことを検査している。木を辿る処理は訪問済みの集合か深さの上限を持つ
- 日付はISO形式、開始日 ≤ 終了日。工数は有限の0以上（分は整数）。列挙値は許可リストで判定している
- `__proto__`・`constructor`・`prototype`のキーを拒否している。パース結果をスプレッドや`Object.assign`で状態にマージせず、検証済みのフィールドだけを詰め替えている。ID辞書は`Map`か`Object.create(null)`
- 検証に失敗したら一部も取り込まず、現在の状態を変えない。エラーは利用者向けの日本語で、生の例外文言を出さない
- スキーマの版を確認し、版ごとの移行のあとに検証している。未来の版は拒否する

### 書き出すCSV
- 先頭が `=`・`+`・`-`・`@`・タブ・CRの文字列を数式として解釈されないよう無害化している（数値の列の負数は誤って無害化しない）。共通のユーティリティで行っている

### 画面表示
- `dangerouslySetInnerHTML`を使っていない（ESLintの`react/no-danger`がerror）
- 自由記述（背景・見積根拠・コメント・CSVの値）はテキストとしてだけ表示し、URLとして`href`に渡していない

## D. データの完全性（CLAUDE.md 4章）

- Baseline・BaselineItem・AuditLog・EvmSnapshotを更新・削除する経路（ドメイン関数、reducerのaction、画面、JSONの読み込み）が無い
- 4章のルールを`src/domain/`のドメイン関数で守らせ、そのテストがある
- JSONの読み込みで、ファイル内の整合（版番号の連続、BaselineItemの参照、各版に対応するAuditLog、改版理由）を検査している
- 現在の状態にベースラインがあるとき、読み込むデータが現在の版・AuditLogを同一の内容で含む（追記のみ）ことを検査している。これは整合性の検証であり、意図的な改ざんは検知できないことが記録されている
- 記録すべき操作（ベースラインの確定・改版、G1+2承認・差戻し、手動の完了・取り消し、権限の変更）がAuditLogに残る
- 実績工数の個人別表示が、権限判定の関数を通っている（本人とPMのみ）

## E. ブラウザの保存（localStorage）

- キーに名前空間（`project_management_poc:`）がある
- 起動時の読込も読み込み検証と同じ関数に通し、失敗したら自動保存を止めて元の値を退避している（空の状態で上書きしない）
- 書き込みの失敗（容量超過など）を消えない表示で利用者に知らせ、JSONの書き出しを促している
- 複数のタブで開いたときに、他のタブの更新で監査ログ等を失わない（`storage`イベントで検知して読み取り専用にする等）
- 保存データを消去する操作がある

## F. CI・依存関係（CLAUDE.md 6.4）

- CIでlint・型チェック・単体テスト・`@security`テスト・依存の脆弱性スキャン・gitleaksを実行している
- 各ワークフローのトップレベルが`permissions: contents: read`。`pages: write`・`id-token: write`はGitHub Pagesへの配信ジョブだけ
- 配信はCIの成功を条件にしている。`concurrency`がある
- トリガーに`pull_request_target`を使っていない
- Actionはコミットsha固定。Dependabot（npm・github-actions）がある
- `package-lock.json`をコミットし、CIは`npm ci`。本番依存はhigh/critical 0件。dev依存の結果とライセンス一覧を確認している
- `vite.config.ts`で開発サーバーを外部に公開していない（`server.host`）

## 人手で確認する項目（テスト不能）

- GitHub Pagesの`github-pages`環境のデプロイ元が`main`に限られている
- `main`のRulesetでCIの成功が必須になっている
- 操作者・承認者が自己申告であることが、評価レポートの課題（権限・監査）に記録されている

## レビュー結果の記録形式

`docs/security/reports/review-YYYYMMDD-HHMM.md`に、以下を出力する。

- サマリ：検査範囲、コミットSHA、重大度別の件数
- 指摘一覧（各指摘に必須の項目）：
  - ID（`SEC-001`）、重大度（Critical/High/Medium/Low/Info）、カテゴリ（本書のA〜F）
  - 該当箇所（`ファイル:行`）、根拠、影響、修正案
  - 対応するテスト（追加したテストファイル名とテスト名）または「テスト不能の理由」
- 該当なしとした項目と、その理由
- テスト実行結果（成功/失敗数、失敗の内訳）
- 秘密情報らしき値・実データは書き写さない（ファイル:行と種類だけを書く）
