## 指摘一覧と対応

### SEC-001 Low　E・D：読み取り専用のタブで、反映されていない操作が成功したように表示される
- 該当箇所：usePersistedState.ts の dispatch、App.tsx の run・onImport、GateReviewPanel.tsx
- 対応：dispatch が「反映したか」を返すようにし、run・読み込み・書き出し日時の記録は、反映できなかったら成功と表示せず理由を出す。読み取り専用の間は、読み込みと消去のボタンを無効にして理由を表示する。消去は読み取り専用のタブでは行わない（別のタブが保存した最新のデータを消さないため。ux-reviewer の指摘）
- 対応するテスト：テスト不能（画面の部品とブラウザのタブをまたぐため、単体テストでは再現できない）。ブラウザ（Chromium）で2つのタブを開き、2つ目で保存すると1つ目で入力が反映されず理由が表示されること、消去ボタンが無効になることを確認した。E2E テストの候補として残す
- 本番コードの修正の承認：この指摘は失敗するテストを伴わない（テスト不能）ため、/security-review の「テスト失敗時の承認」の対象外とし、ux-reviewer の同じ指摘（高）への対応として修正した

### SEC-002 Info　C：ファイルの大きさの確認が、全体を読んだ後
- 対応：`file.size` が上限を超えたら読む前に断る。読み込みの途中で別のファイルを選んだら、古い結果で上書きしない

### SEC-003 Info　E：消去の確認で、退避データの書き出しを促していない
- 対応：退避データがあるときは、消去の確認に「退避したデータを書き出す」を出す。保存データを読めなかった警告にも、退避データを書き出せることを書く

### SEC-004 Info　E：自動保存が止まっているときも「入力は自動で保存されます」と表示する
- 対応：自動保存が止まっているときは、初回の案内の文言を変える

### SEC-005 Info　D・E：書き出し日時が未来だと、書き出しの促しが出なくなる
- 対応：書き出し日時が今より後なら、端末の時計の確認と書き出しを促す（`futureExport`）。テストあり

### SEC-006 Info　E：ダウンロードの直後に Blob URL を解放している
- 対応：解放を1秒遅らせる

### SEC-007 Info　D：目的の削除と、PMの氏名の変更が監査ログに残らない
- 対応：目的の削除を監査ログに残す（目的のコード・内容・紐付いていたWPの数）。権限の変更の監査ログに、メンバーのIDとその時点の氏名を残す（logic-reviewer の指摘）
- 見送り：氏名の変更そのものは監査ログに残さない（入力のたびに記録が増えるため）。操作者・承認者は自己申告であり、その氏名を後から変えられることは、評価レポートの「権限・監査」の課題に書く
