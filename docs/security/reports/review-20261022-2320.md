## 指摘と対応
### SEC-001 Low（JSONの読み込み）スナップショットの工数に上限が無い
- 内容：BAC・PV・EV・AC が 1e307 のように巨大でも、指標の整合性の検査に通る。CSVに丸めて書くときに無限大になり、書き出せなくなる
- 対応：4つの値に上限（`LIMITS.maxSnapshotHours`＝1億時間）を設けた。あわせて、BAC がその版の明細の計画工数の合計と一致すること、PV・EV が BAC を超えないことを検査する（logic-reviewer の指摘）。`[@security]` テストを追加（`snapshot.test.ts`）

### SEC-002 Info（CSV出力）数式の対策
- 問題なし。負のずれは数値のセルとして書き、`'` が付かないことを `[@security]` テストで確認している

### SEC-003 Info（データの完全性）AC・EV は読み込み時に求め直さない
- 内容：AC・EV は後の実績・完了の変更で変わりうるため、記録した値をそのまま受け入れる。値をそろえて書き換えたJSONは、保存データが空のブラウザで読み込むと通る（作成後の変更は、現在のデータとの比較で防いでいる）
- 対応：変更しない（人間の判断：作成の操作は監査ログに記録しない）。評価レポート（8.6）の「監査」の残る課題に挙げる

### SEC-004 Info（巨大入力）スナップショットごとに版を探す
- 対応：版を表（Map）にしてから比べるようにした

### SEC-005 Info（移行）版2→3の移行
- 問題なし。知っている項目だけを詰め替え、スナップショットのある版2のデータは拒否する。禁止キーの検査は移行より前に行う
