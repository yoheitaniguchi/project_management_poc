## 指摘一覧と対応

### SEC-001 Medium　監査ログの切り詰めで、改版で外したWPの記録が消える
- 対応：改版理由と外す理由を500文字以内にした（ドメイン関数・読み込み時の検証・入力欄）。外したWPは、WPごとに監査ログ（`baseline.exclude`）を1件ずつ残し、理由を全文で記録する。改版の監査ログ（`baseline.revise`）には外したWPのコードとコメントを入れる
- 対応するテスト：`baseline.test.ts`「長い改版理由・複数の外すWPでも、監査ログは JSON として読め、外したWPと理由が全文で残る」

### SEC-002 Low　計画期間の上限が無く、営業日の計算で画面が固まる
- 対応：確定できない理由の判定は、営業日が1日でも見つかったら止める関数（`hasBusinessDay`）に変えた。祝日は Set で照合する。計画日の年を2000〜2099年に制限した（編集・読み込み時の検証・入力欄）
- 対応するテスト：`calendar.test.ts`「営業日が1日でもあるかは、長い期間でもすぐに判定できる」、`wbs.test.ts`・`validate.test.ts` の年の範囲のテスト

### SEC-003 Low　過去の版の明細に対象外のWPを許した検査が、改版で外したWPに限られていない
- 対応：過去の版の明細にある対象外のWPは、次の版の明細に無いこと（次の版で外れていること）を求める
- 対応するテスト：`validate.test.ts`「過去の版の対象外のWPが、次の版にも残っているデータを拒否する」

### SEC-004 Info　改版で外したWPを、監査ログを残さずに対象に戻せる
- 対応：変更しない。4章の監査対象（確定・改版・承認・権限の変更）に入らない。外した理由は SEC-001 の対応で監査ログに全文で残るので、後から確かめられる

### SEC-005 Info　applyExclusions が配列の要素の型を確かめていない
- 対応：要素がオブジェクトで、wbsNodeId が文字列であることを確かめ、そうでなければ理由を付けて拒否する
- 対応するテスト：`baseline.test.ts`「改版の入力の誤りを、理由を付けて拒否する」

### SEC-006 Info　改版の監査ログにコメントが無い
- 対応：改版の監査ログにコメントを入れた（画面のレビューの L5 と同じ対応）
