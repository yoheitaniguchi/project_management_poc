## 指摘と対応
### SEC-001 Low（書き出すCSV）全角の記号や先頭の空白に続く数式記号を無害化していない
- 対応：先頭の空白（半角・全角）の後に続く `= + - @`、全角の `＝ ＋ － ＠`、タブ・改行で始まる値にも `'` を付ける
- 対応するテスト：`csvWrite.test.ts`「[@security] 先頭が数式として解釈されうる値…」「[@security] WP名に数式を入れても…」

### SEC-002 Low（書き出すCSV）共通の書き出し関数に、数値の列を無害化から外す仕組みが無い
- 対応：`toCsv` が有限の数値をそのまま書けるようにした（負の数に `'` が付かない）。有限でない数値は書き出さずに例外にする。3週目のスナップショットのCSV出力で使う
- 対応するテスト：`csvWrite.test.ts`「数値はそのまま書く…」

### SEC-003 Low（データの完全性）JSONの読み込みで、完了日と監査ログの対応を検査していない
- 対応：WPの完了日は、そのWPの最後の完了の操作（`wbs.complete` の記録の完了日、または `wbs.uncomplete` なら空）と一致しなければ読み込まない。記録の無い完了日の書き換えは拒否する
- 対応するテスト：`completion.test.ts`「読み込み時の検証：完了日が監査ログの最後の完了の操作と合わないデータは拒否する」

### SEC-004 Low（データの完全性）完了したWPを削除しても監査ログに残らない
- 対応：完了になっているWPを含む要素は削除できない（先に完了を取り消す。取り消しは監査ログに残る）
- 対応するテスト：`completion.test.ts`「完了のWPは削除できない…」

### SEC-005 Info（テスト）数式インジェクション対策に `@security` テストが無い
- 対応：SEC-001 のテストに `[@security]` を付けた（`npm run test:security` で実行される）
