## 指摘一覧と対応

### SEC-001 Medium　F・6.1：プレビューの配信がCIの検査と無関係で、本番と同じオリジンにPRのコードを出す
- 対応：プレビューの build ジョブで、本番の配信と同じ検査（lint・型チェック・単体テスト・本番依存の脆弱性 high/critical）を通してからビルドする
- 残るリスク：同じオリジンのため、プレビューのコードは技術的には本番の保存データを読める。PRを作れるのはリポジトリに書き込める人だけで、フォーク・DependabotのPRは対象外のため受け入れる。CR-003 と README に記録した（監理者の判断を求める）

### SEC-002 Low　F：Actionのshaとタグの対応、外部Actionの内側のAction
- 対応：上流の `git ls-remote` で、upload-artifact v7.0.2=cf430e03…、download-artifact v8.0.2=9000827c…、peaceiris/actions-gh-pages v4.1.0=84c30a85…（注釈付きタグの参照先）、rossjrw/pr-preview-action v1.8.1=ffa7509e… を確かめた。rossjrw の固定したshaの `action.yml` では、内側の JamesIves/github-pages-deploy-action（v4.7.4）と marocchino/sticky-pull-request-comment（v2.9.2）もshaで固定されている

### SEC-003 Low　F（可用性）：本番の配信とプレビューの配信が、同時に gh-pages へ push しうる
- 対応：変更しない。共通の concurrency グループにすると、待っている本番の配信が後から来たプレビューに取り消されるおそれがあるため。競合したときは配信のジョブが失敗として見えるので、再実行で対応する

### SEC-004 Low　A・6.1：keep_files で一度配信したファイルが残る。dist が無いときに検査が成功扱いになる
- 対応：`scripts/check-dist.sh` で dist が無ければ失敗にする。誤って配信したファイルは gh-pages から手で削除する手順を README に書いた

### SEC-005 Low　F：@security テストの抜け
- 対応：ワークフロー×ジョブ→認める書き込み権限の表で照合する。書き込み権限を持つジョブでは `run:` を禁止する。コメントを除いてから数える。pr-preview.yml のすべてのジョブが、フォークとDependabotのPRを除く条件を持つことを確かめる
- 対応するテスト：`security/repo-hygiene.security.test.ts`。わざと違反（id-token: write の追加、配信のジョブへの run の追加、persist-credentials をコメントにする、build ジョブへの write、フォークの条件の削除）を入れ、それぞれ失敗することを確かめた

### SEC-006 Info　6.1：PRを閉じた後も、プレビューの保存データがブラウザに残る
- 対応：プレビューの表示に「実データは入れない」「保存データはPRを閉じた後も残る」ことを書いた

### SEC-007 Info　F：Pagesのソースが gh-pages ブランチに変わり、環境による保護が無くなる
- 対応：チェックリストの人手確認の項目を更新済み。マージ後に Settings → Pages の Source が `gh-pages` / `(root)` になっていることを人が確かめる
