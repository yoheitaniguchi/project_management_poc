## 指摘と対応
### SEC-001 Info（F. CI・依存関係）開発用の依存 minimatch 10.2.6 に、サービス妨害（DoS）の勧告がある
- 該当箇所：`package-lock.json` の `node_modules/minimatch`（10.2.6）。eslint（`^10.2.5`）、@eslint/config-array（`^10.2.4`）、@typescript-eslint/typescript-estree（`^10.2.2`）が使う。直接の依存ではない
- 根拠：GHSA-g3hv-75wg-m249 / CVE-2026-118764（2026-10-27 公開。CVSS v4.0 6.9、Moderate）。glob のパターンを細工すると、前処理でパターンが増え、その後の総当たりの比較で CPU とメモリを使い切る。直った版は 11.0.1
  - 起こる条件：(1) 攻撃者が glob のパターンを渡せること（照合されるパスではない）、(2) `optimizationLevel` が 2 以上であること
- 影響：このリポジトリでは起こせない
  - 条件(2)を満たさない：minimatch 10.2.6 の `optimizationLevel` の既定値は 1 である。上の3つのパッケージのコードには `optimizationLevel` を指定する箇所が無く、渡す設定は `{ dot: true }` だけである（`node_modules` を検索して確認した）
  - 条件(1)を満たさない：パターンの出どころは、このリポジトリの `eslint.config.js` と lint のコマンドの引数だけである。外部から読み込むファイル（Asana の CSV、保存した JSON）は ESLint に渡らない
  - ESLint は開発者の PC と CI だけで動き、配信物（`dist`）には入らない。また、`eslint.config.js`（JavaScript）を書き換えられる者は、もともと任意のコードを実行できるため、この勧告で危険が増えることはない
  - 影響は可用性（DoS）だけである。勧告には、任意のコードの実行や情報の漏えいの記載は無い
- 修正案と、採らない理由：
  - `npm audit fix --force`：eslint を 4.0.0 に下げる案になる。直る版が他に無いときの npm の機械的な提案で、採らない
  - `package.json` の `overrides` で minimatch を 11 に強制する：最新の eslint 10.14.0 も `^10.2.6` を前提にしており、11 で動くかは確かめられていない（11 で一部の関数が無くなったという外部の報告がある）。11.0.1 にも問題の行が残っていて直っているか疑わしい、という外部の指摘もある。PoCの期間に確かめる工数に見合わない
  - 採る対応：何もしない（リスクを受け入れる）。eslint などが minimatch 11 に対応すれば、Dependabot のマイナー・パッチの更新（`npm-minor-and-patch`）で入る見込み。入った後に `npm audit` で勧告が消えたことを確かめる
- CI への影響：CI を失敗にする監査は `npm audit --omit=dev --audit-level=high` で、開発用の依存の moderate は対象外のため、CI は失敗しない。開発用の依存を含む監査（`npm audit || true`）の表示と、GitHub の Dependabot アラートには出続ける
- 対応するテスト：テスト不能の理由。依存のパッケージの内部（minimatch に渡す設定）の確認であり、このリポジトリのコードには検査する対象が無い。依存を更新したときは、`npm audit` の結果で確かめる
