# 変更要求の記録

PoCの範囲外の機能・改善や、計画の変更は、実装せずにここへ記録する（CLAUDE.md 9章）。
判断は人間（監理者）が行い、承認されたものだけを実装する。記録する前に `change-request-reviewer` で内容を確認する。

## 書式

```markdown
### CR-NNN 件名
| 項目 | 内容 |
| --- | --- |
| 記録日 | YYYY-MM-DD |
| 内容 | 何をどう変えるか |
| きっかけ | 実際に起きた出来事 |
| 計画内か外か | 計画内／計画外（CLAUDE.md 3.1・3.2に照らして） |
| 工数と日程への影響の見込み | 軽／中／重と、根拠 |
| 寄与する目的 | O1〜O3のどれか、または「なし」 |
| 判断 | 未判断／承認／却下（判断日・判断者） |
```

| 内容 | 姉妹リポジトリ `production_system_sim` と同じく、PRごとのプレビューを `gh-pages` ブランチの `pr-preview/pr-<番号>/` に配信し、PRにURLをコメントする。本番の配信も `actions/deploy-pages` から `gh-pages` ブランチへのpushに切り替える。プレビューは本番と同じオリジンで開くため、保存先（localStorage）の名前空間を本番と分け、画面にプレビューであることを表示する |

### CR-004 取り込んだ実績工数を取り消せるようにする
| 項目 | 内容 |
| --- | --- |
| 記録日 | 2026-10-22 |
| 内容 | 実績工数のCSV取込（8.2、取込元 `manual_csv`）で取り込んだ実績を、画面から取り消せるようにする。取り消しはドメイン関数で行い、確認ダイアログを経て実行する。取り消した実績の値（作業日・WP・時間・メモ・一意キー）を変更前の値としてAuditLogに追記する。取込履歴（SyncRun）は変更・削除しない。取り消した実績の一意キーは消えるため、正しい内容のCSVを取り込み直して直す。週次スナップショットは作成後に変更しない（取り消し後は、スナップショットのACと再計算した値が合わなくなることを許容する）。取り消しの単位は「取込（SyncRun）単位」か「実績1件単位」のどちらかで、監理者が決める。現状では TimeEntry を減らす操作が無く、時間・作業日・WPを誤って取り込むと画面から直せない。また、一意キーが「作業日・WPのID・メモ」のため、メモを変えて取り込み直すと二重になる（取込時に警告は出す） |
| きっかけ | PR-H のレビューで、logic-reviewer・ux-reviewer・security-reviewer の3つがそろって指摘した。取込済みと時間が違う行のエラー文が、存在しない「消す」操作を案内していた（文言は修正済み。`src/domain/timeImport.ts`）。実データでの誤取込はまだ起きていない（PoCの実データは10/26から） |
| 計画内か外か | 計画外（3.1 F08と8.2は、取込・冪等性・失敗時の扱いまで。取り消しの操作は含まない） |
| 工数と日程への影響の見込み | 取込単位なら重：TimeEntry に取込履歴のIDが無いため、データモデルの変更（項目の追加、スキーマ版2→3の移行、JSON読み込みの検証の変更）を伴う。実績1件単位なら中：データモデルは変えず、ドメイン関数・監査ログ・画面のボタンと確認ダイアログを足す。どちらも人間のレビュー・受け入れは30〜60分程度（破壊的な操作のため、セキュリティレビューを含む）。それまでの代わりの手運用：JSONを書き出し、該当する `timeEntries` の要素を消して読み込む（読み込み時の検証で不正なデータは拒否される。ただし監査ログには残らないので、週次報告に記録する） |
| 寄与する目的 | O2（間接）：成功指標の「週次記録率」そのものは上がらないが、AC（CPI・EAC・消化率）の正確さを保ち、中核ループの「実績を取り込む→差異を示す」の信頼性に寄与する。誤取込がまだ起きていないため、効果は発生頻度しだい |
| 判断 | 保留（2026-10-22、監理者）。PoC中は「工数と日程への影響の見込み」に書いた手運用（JSONを書き出して該当の実績を消し、読み込む。週次報告に記録する）で対応し、実際に誤って取り込んだときに改めて判断する |
