# 変更要求の記録

PoCの範囲外の機能・改善や、計画の変更は、実装せずにここへ記録する（CLAUDE.md 9章）。
判断は人間（監理者）が行い、承認されたものだけを実装する。記録する前に `change-request-reviewer` で内容を確認する。

## 書式

```markdown
### CR-NNN 件名
| 項目 | 内容 |
| --- | --- |
| 記録日 | YYYY-MM-DD |
| 内容 | 何をどう変えるか |
| きっかけ | 実際に起きた出来事 |
| 計画内か外か | 計画内／計画外（CLAUDE.md 3.1・3.2に照らして） |
| 工数と日程への影響の見込み | 軽／中／重と、根拠 |
| 寄与する目的 | O1〜O3のどれか、または「なし」 |
| 判断 | 未判断／承認／却下（判断日・判断者） |
```

## 一覧

### CR-001 AsanaのCSV取込を4週目に回し、週の計画を組み替える
| 項目 | 内容 |
| --- | --- |
| 記録日 | 2026-10-21 |
| 内容 | AsanaのCSVからの取込（8.2）を4週目に移す。代わりに2週目で、独自書式のCSVによる実績の入力、WPの完了の手動設定（5章の一時変更）、Asanaインポート用CSVの書き出し、簡易EVMの計算を行う。3週目は週次監視画面。8.2の完了条件「実際のAsanaのCSVで取込を1回確認」は4週目へ移る |
| きっかけ | AsanaからCSVを書き出して用意するのに時間がかかるため（監理者の指示） |
| 計画内か外か | 計画内（F08・F09の実施順と、5章の完了判定の一時変更） |
| 工数と日程への影響の見込み | 軽：作る機能は同じで順番が変わるだけ。独自書式CSVの取込と手動完了の分だけ実装が増えるが、人間の工数への影響は小さい。Asana取込が4週目に寄るため、間に合わない場合は評価レポートに未検証として記録する |
| 寄与する目的 | O2（実績の記録と差異の計数化を、Asanaの準備を待たずに始められる） |
| 判断 | 承認（2026-10-21、監理者） |

### CR-002 vite を 5 から 8 へ更新し、テストとビルドの vite のメジャー版を揃える
| 項目 | 内容 |
| --- | --- |
| 記録日 | 2026-10-21 |
| 内容 | vite 5.4.21 と @vitejs/plugin-react を、vitest 4 が使っている vite 8 系に揃えて更新する |
| きっかけ | PR-B のセキュリティレビュー（`docs/security/reports/review-20261021-0948.md` SEC-001・SEC-005）。vite 5 に開発サーバーに関する high の勧告があり、修正にはメジャー更新が必要。また、テスト（vite 8）とビルド（vite 5）で同じ設定が別のメジャー版で評価されている |
| 計画内か外か | 計画外（依存の保守。3.1の機能には含まれない） |
| 工数と日程への影響の見込み | 軽〜中：設定（vite.config.ts）の互換性確認とビルド・テストの再確認が必要。人間のレビューは30分程度。開発サーバーは localhost のみで、配布物に脆弱性は無いため、急ぐ必要は低い |
| 寄与する目的 | なし（PoCの品質・安全性の維持） |
| 判断 | 承認（2026-10-21、監理者）。Dependabot の #5・#8 と、minor・patch の更新 #4 をまとめた1つのPRで対応する |

### CR-003 PRごとに変更をプレビューできるようにする
| 項目 | 内容 |
| --- | --- |
| 記録日 | 2026-10-22 |
| 内容 | 姉妹リポジトリ `production_system_sim` と同じく、PRごとのプレビューを `gh-pages` ブランチの `pr-preview/pr-<番号>/` に配信し、PRにURLをコメントする。本番の配信も `actions/deploy-pages` から `gh-pages` ブランチへのpushに切り替える。プレビューは本番と同じオリジンで開くため、保存先（localStorage）の名前空間を本番と分け、画面にプレビューであることを表示する |
| きっかけ | 監理者の要望（PRの変更を、マージ前に画面で確認したい） |
| 計画内か外か | 計画外（配信の仕組みの変更。3.1の機能には含まれない） |
| 工数と日程への影響の見込み | 軽：PR1本。人間の作業はレビュー15分程度と、Settings → Pages の Source の変更、プレビューの動作確認。以降のPRでは、受け入れの確認がブラウザでできるため、レビューの時間が減る見込み |
| 寄与する目的 | なし（PoCの進め方の改善。レビューと受け入れの確認を早くする） |
| 判断 | 承認（2026-10-22、監理者）。CIの書き込み権限を配信のジョブ（deploy・preview）に広げ、それに合わせて `@security` テストを変更することも承認 |
| 残るリスク | プレビューは本番と同じオリジンで動くため、PRのコードは技術的には本番の保存データを読み書きできる（保存先の分離はアプリの約束事）。PRを作れるのはリポジトリに書き込める人だけで、フォークとDependabotのPRは対象外。プレビューはCIと同じ検査に通ったものだけを配信する（`docs/security/reports/review-20261022-0340.md` SEC-001） |
