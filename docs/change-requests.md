# 変更要求の記録

PoCの範囲外の機能・改善や、計画の変更は、実装せずにここへ記録する（CLAUDE.md 9章）。
判断は人間（監理者）が行い、承認されたものだけを実装する。記録する前に `change-request-reviewer` で内容を確認する。

## 書式

```markdown
### CR-NNN 件名
| 項目 | 内容 |
| --- | --- |
| 記録日 | YYYY-MM-DD |
| 内容 | 何をどう変えるか |
| きっかけ | 実際に起きた出来事 |
| 計画内か外か | 計画内／計画外（CLAUDE.md 3.1・3.2に照らして） |
| 工数と日程への影響の見込み | 軽／中／重と、根拠 |
| 寄与する目的 | O1〜O3のどれか、または「なし」 |
| 判断 | 未判断／承認／却下（判断日・判断者） |
```

## 一覧

### CR-001 AsanaのCSV取込を4週目に回し、週の計画を組み替える
| 項目 | 内容 |
| --- | --- |
| 記録日 | 2026-10-21 |
| 内容 | AsanaのCSVからの取込（8.2）を4週目に移す。代わりに2週目で、独自書式のCSVによる実績の入力、WPの完了の手動設定（5章の一時変更）、Asanaインポート用CSVの書き出し、簡易EVMの計算を行う。3週目は週次監視画面。8.2の完了条件「実際のAsanaのCSVで取込を1回確認」は4週目へ移る |
| きっかけ | AsanaからCSVを書き出して用意するのに時間がかかるため（監理者の指示） |
| 計画内か外か | 計画内（F08・F09の実施順と、5章の完了判定の一時変更） |
| 工数と日程への影響の見込み | 軽：作る機能は同じで順番が変わるだけ。独自書式CSVの取込と手動完了の分だけ実装が増えるが、人間の工数への影響は小さい。Asana取込が4週目に寄るため、間に合わない場合は評価レポートに未検証として記録する |
| 寄与する目的 | O2（実績の記録と差異の計数化を、Asanaの準備を待たずに始められる） |
| 判断 | 承認（2026-10-21、監理者） |
