---
description: レビュー→指摘対応テスト追加→テスト実行→レポート出力までを自動化するセキュリティレビュー
argument-hint: "[--all]"
---

このリポジトリのセキュリティレビューを、`CLAUDE.md` 6.3・6.4・4章の観点（`docs/security/checklist.md`があれば併せて）で実行する。
引数は `$ARGUMENTS` （`--all`が指定されていれば全体、無指定なら差分のみが対象）。

## 1. スコープ決定

- 引数に`--all`が含まれる場合：リポジトリ全体（コード・設定ファイル・CI・依存関係・コミット履歴）を対象にする
- 引数が無い場合：`git diff main...HEAD --name-only`で変更ファイル一覧を取得し、それらを対象にする
  （変更が無い場合はその旨を報告して終了する）
- 併せて`git rev-parse HEAD`でコミットSHAを取得しておく（レポートのサマリに使う）

## 2. レビュー

`security-reviewer`サブエージェント（Agentツール、`subagent_type: security-reviewer`）を起動し、
上記スコープを伝えて検査させる。読み取り専用・Bashは監査コマンドのみ（サブエージェント自身のフックで強制済み）なので、
本番コードが変更される心配は無い。

結果を受け取ったら、`docs/security/reports/review-YYYYMMDD-HHMM.md`（実行時刻）を作成する。
サマリ（検査範囲・コミットSHA・重大度別件数）と指摘一覧（ID・重大度・カテゴリ・該当箇所・根拠・影響・修正案）、
該当なしとした項目・理由を記載する。**秘密情報らしき値はレポートに書き写さない**（ファイル:行と種類だけを書く）。

## 3. テスト追加

重大度がInfo以外の指摘それぞれについて、`security-test-writer`サブエージェント
（`subagent_type: security-test-writer`）を起動し、指摘内容（該当箇所・根拠・重大度・カテゴリ）を渡してテストを追加させる。
このサブエージェントはテストファイル以外を編集できない（フックで強制済み）ため、本番コードが誤って書き換えられることは無い。

- 1指摘ずつ呼び出してもよいし、関連する指摘をまとめて1回で渡してもよい
- 返ってきた「対応するテスト（ファイル名・テスト名）」または「テスト不能の理由」を、レポートの対応する指摘の下に追記する
- テストを動かす環境（`package.json`・テストランナー）がまだ無い場合は、この手順をスキップし、その旨をレポートに書く

## 4. 実行

`@security`タグ付きのテストを実行する（`package.json`に`test:security`があれば`npm run test:security`、
無ければ`npx vitest run -t "@security"`）。実行結果（成功/失敗数、失敗したテスト名）をレポートの末尾に追記する。

## 5. 判定と報告

- **全テスト成功**：レポートを完成させ、ユーザーへ完了報告する
- **失敗あり**：失敗したテスト＝脆弱性が顕在化したものとして扱う。該当する指摘の修正案（差分イメージ）を提示し、
  **ここで一旦停止してユーザーの承認を待つ**。本番コードの修正は、ユーザーが承認するまで絶対に行わない
  - 承認を得たら、提案どおりに本番コードを修正し（このコマンドを実行している本体セッションが行う。
    `security-reviewer`・`security-test-writer`はどちらも本番コードを編集できない）、テストを再実行する
  - この「修正→再実行」のループは最大3回までとする。3回で解消しない場合は、状況（何が失敗し続けているか、
    試した修正、推測される原因）を報告してループを終了する
  - 再実行のたびにレポートを更新する

## 6. 承認が必要な操作

次の操作は修正案として提示するだけに留め、**ユーザーの事前承認を得るまで実行しない**（CLAUDE.md 0章・6.4）。

- 依存パッケージの追加・大幅なアップデート（`npm audit fix --force`等）
- CI設定・`.gitignore`・GitHub Actionsワークフローの変更
- コミット履歴に混入した秘密情報の除去（履歴の書き換え）と、該当トークンの失効・再発行の依頼
- pushなどリポジトリ外への反映

## 補足

- テストや検証で、実際のAsana・外部サービス・第三者システムへ通信しない（CLAUDE.md 6.2）
- `security-reviewer`・`security-test-writer`のいずれも設定変更・依存インストール・ネットワークアクセスができないため、
  それらが必要な作業（gitleaksの導入、CIへのスキャン追加等）は、本体セッションがユーザーへの提案・承認を経てから行うこと
